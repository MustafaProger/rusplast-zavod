# Гид по проекту «РуспластЗавод»

Для обычной работы с материалами откройте [инструкцию редактора CMS](CMS_CONTENT.md). Этот документ посвящён запуску, проверкам и публикации приложения. Он описывает обновлённую реализацию; факт её развёртывания на публичном домене подтверждается отдельным отчётом о релизе.

## Откуда сайт берёт содержимое

Strapi хранит записи «Товар», «Статья», «Документ» и «Заявка». Изображения и PDF находятся в **Media Library**, текст статьи — в записи «Статья». Клиентские заявки не становятся содержимым блога и не используются оператором для генерации изображений.

Production web — сервер Node, который получает опубликованное содержимое Strapi и формирует страницу вместе с текстом, SEO-разметкой и актуальными ссылками. Он также формирует `/sitemap.xml` и `/publication-manifest.json`. Кеш по умолчанию — 15 секунд. Новую публикацию проверяют после этого интервала новым запросом страницы; уже открытая вкладка не обязана обновиться сама.

Правка CMS не требует пересборки web. Новая версия кода, дизайна, схем CMS или правовых документов требует обычного релиза приложения. Изменение кода локально не обновляет публичный сервер.

## Первый запуск

Используйте Node.js 22 и npm. Для CMS настройте исключённый из Git `cms/.env` по образцу `cms/.env.example`; примерные ключи не подходят для рабочей установки. Для браузерного API в разработке предусмотрен `web/.env.example`.

Из корня репозитория:

```sh
npm ci --prefix cms
npm ci --prefix web
npm run dev:cms
```

В другом терминале:

```sh
npm run dev:web
```

Сайт доступен на [localhost:5173](http://localhost:5173), панель CMS — [localhost:1337/admin](http://localhost:1337/admin). Первый администратор создаётся только для новой пустой установки. Для существующей CMS используйте действующую учётную запись.

Локальная CMS использует SQLite в `cms/.tmp/`. Остановка сервера: `Ctrl+C`. Удаление файла базы означает потерю локальных данных — для обычного перезапуска это не нужно.

## Первоначальный перенос и Excel

При запуске CMS автоматического заполнения seed-данными больше нет. Чтобы перенести существующий сайт, выполните [инструкцию миграции](../cms/CONTENT-MIGRATION.md): подготовка пакета, резервная копия, проверка без записи и отдельное применение. Пакет включает товары, статьи, PDF и изображения. Повтор завершённой миграции не создаёт дубликаты и не восстанавливает удалённые редактором записи.

`data/` и `scripts/extract_products.py` сохраняют исходный Excel и средство извлечения данных. Их результат — материал для подготовки импорта, а не команда обновления опубликованного каталога. Для текущих правок пользуйтесь CMS. Новый массовый импорт нужно отдельно сверять по артикулам и ценам; перезапуск приложения не импортирует изменённый Excel.

## Снимок CMS, сборка и два режима просмотра

Команда снимка **читает**, но не изменяет CMS:

```sh
npm run cms:sync --prefix web
```

По умолчанию используется `https://cms.rusplast-zavod.ru`. Для локальной CMS:

```sh
CMS_URL=http://localhost:1337 CMS_PUBLIC_URL=http://localhost:1337 npm run cms:sync --prefix web
```

Результат сохраняется в `web/src/data/cms-snapshot.json`. Он нужен для воспроизводимой сборки, разработки и статического предпросмотра. Это не дополнительная редакторская база. Не редактируйте его вместо Strapi и не ожидайте, что изменения файла появятся в CMS.

Сборка и базовые проверки из корня:

```sh
npm run build --prefix web
npm run build --prefix cms
npm run lint --prefix web
node --test cms/tests/lead-consent.test.cjs cms/tests/notification.test.cjs
```

Web создаёт клиентские ресурсы и статический снимок в `web/dist`, а также серверный модуль в `web/dist-server`.

| Команда | Назначение |
| --- | --- |
| `CMS_INTERNAL_URL=http://localhost:1337 CMS_PUBLIC_URL=http://localhost:1337 npm run start --prefix web` | Runtime Node с актуальной CMS; по умолчанию порт 4173 |
| `npm run preview --prefix web` | Статический предпросмотр последней сборки из `dist`; по умолчанию порт 4173 |
| `npm run dev:web` | Vite для работы над интерфейсом; видимый начальный снимок не доказывает доступность CMS |

Одновременно запускать два сервера на порту 4173 нельзя. Для runtime задайте `PORT`; для статического предпросмотра можно передать `-- --port 4174`.

Публикация/снятие с публикации в CMS автоматически отражаются в runtime, включая текст страницы и sitemap, после обновления кеша. Статический preview остаётся снимком на момент сборки. При недоступной CMS runtime после окончания кеша возвращает 503 и не возвращает ранее удалённые записи из seed.

## Проверки интерфейса и CMS

```sh
npm run qa:visual
npm run qa:seo --prefix web
```

Для `qa:visual` запустите web по адресу, заданному `QA_BASE_URL` (по умолчанию `http://127.0.0.1:5175`); адрес должен совпадать с реально работающим сервером. `qa:seo` проверяет готовую статическую сборку и интерфейс с тестовыми API-данными. Эти проверки не заменяют проверку runtime и публичного сайта после релиза.

Проверки миграции и CMS выполняются из `cms/`:

```sh
npx strapi ts:generate-types
npx tsc
node --test tests/content-migration.test.cjs tests/article-content.test.cjs
```

Они используют отдельную временную базу. Подробности и ограничения — в [инструкции миграции](../cms/CONTENT-MIGRATION.md).

Старый скрипт `cms/scripts/cms-smoke.cjs` изменяет выбранную базу: создаёт тестовый товар, а `--cleanup` удаляет его **и заявки с email `qa@example.com`/`test@example.com`**. Он не нужен редактору и не должен быть обычной проверкой production. Для безопасной регрессии предпочтительны тесты с отдельной базой и заглушками. Реальная отправка формы может отправить письмо менеджеру.

## Заявки, согласие и SMTP

Сотрудники работают в **Content Manager → Заявка**. Запись сохраняется до попытки отправить уведомление. Поля `notificationStatus`, `notificationSentAt`, `notificationMessageId` помогают отличить сохранённую заявку от принятого SMTP уведомления. Ошибка письма не означает потерю заявки; автоматического повтора нет.

SMTP задаётся только в серверном окружении (`SMTP_HOST`, `SMTP_PORT`, `SMTP_SECURE`, `SMTP_USER`, `SMTP_PASSWORD`, `LEAD_EMAIL_TO`). Пароли нельзя добавлять в `VITE_*`, Git, логи или переписку. После изменения серверного окружения нужен перезапуск CMS.

API принимает отдельное согласие действующей редакции, сохраняет его текст/время и не предоставляет публичное чтение заявок. `retentionExpiresAt` — предельный контрольный срок, а не автоматическая очистка. Достижение цели или отзыв могут требовать удаления раньше. Ответственный должен учитывать CMS, почту и резервные копии. Проверка уведомления Роскомнадзора, размещения баз, договоров исполнителей и процедуры удаления описана в [аудите персональных данных](PRIVACY_REVIEW-2026-09-23.md).

## Artel Operator

Оператор читает актуальные товары, статьи и документы CMS, подготавливает новую статью, генерирует и проверяет реалистичную обложку, загружает её в Media Library и публикует запись «Статья». Действующие материалы не надо переносить вручную в `generated-articles.json`.

Для работы нужны Mac со службой оператора, доступ к Codex CLI и генерации изображений, интернет и существующий SSH-доступ. Публикация считается подтверждённой после проверки статьи, sitemap и manifest сайта. Настройка, ограничения, повтор после ошибки и команды: [SEO_AUTOPUBLISH.md](SEO_AUTOPUBLISH.md).

## Выпуск приложения

Сначала соберите web:

```sh
npm run build --prefix web
```

Для нового web Docker-образа необходимы `web/dist`, `web/dist-server`, `web/scripts/server.mjs` и `web/package.json`. Образ запускает `scripts/server.mjs` на Node. Одного `dist` и статического Nginx для этой схемы недостаточно.

Настройки:

| Переменная | Где применяется |
| --- | --- |
| `VITE_SITE_URL` | При сборке: canonical-адреса и домен sitemap |
| `VITE_CMS_URL` | При сборке: доступный браузеру адрес API |
| `CMS_INTERNAL_URL` | На сервере web: внутренний адрес Strapi, например `http://cms:1337` внутри сети Compose |
| `CMS_PUBLIC_URL` | На сервере web: публичный HTTPS-адрес CMS для файлов Media Library |
| `CONTENT_CACHE_MS` | На сервере web: время кеша содержимого; по умолчанию 15000 мс |

Перед изменением схем CMS и переносом файлов сделайте согласованную копию PostgreSQL и uploads. Применяйте миграцию по её инструкции и сохраняйте предыдущий выпуск для восстановления. При изменении версии согласия CMS и web обновляются согласованно; старая открытая вкладка формы потребует обновления.

Маршрутизация и резервное копирование описаны в [production-инструкции](../deploy/rusplast/README.md) и [проверке восстановления](../deploy/rusplast/BACKUP.md). Статический `deploy/nginx-static.conf.example` относится к прежнему способу раздачи. Старые SEO-отчёты фиксируют историю проекта и не заменяют эту инструкцию.

После релиза отдельно проверяют публичные HTTPS-страницы, изображения и PDF из CMS, появление опубликованной статьи в HTML/sitemap, сокрытие черновика, настоящий 404, отсутствие публичного доступа к заявкам и отклонение некорректной формы. Сборка и здоровый контейнер сами по себе не подтверждают эти результаты.

## Если изменения не видны

- **Материал сохранён, но на сайте прежний:** проверьте **Publish**, подождите около 15 секунд и заново откройте страницу. Черновик не заменяет опубликованную версию.
- **В Media Library появился файл, а карточка не изменилась:** назначьте файл соответствующему `photo`, `image` или `file` в записи, затем опубликуйте запись.
- **Статический preview не обновляется:** это снимок; для проверки связи с CMS запустите `npm run start --prefix web` с правильными адресами CMS.
- **Новый runtime отвечает 503:** проверьте доступность CMS и всех четырёх коллекций; старый seed не используется для скрытого восстановления материала.
- **Форма не отправляется после обновления:** обновите страницу и повторно подтвердите согласие. Перед этим сохраните при необходимости введённый комментарий; контакты не сохраняются в localStorage.
- **Изменения кода не появились на домене:** нужен релиз приложения. Для опубликованных изменений контента на уже обновлённом runtime релиз не нужен.
