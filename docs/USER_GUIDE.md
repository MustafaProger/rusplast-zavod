# Гид по проекту «РуспластЗавод»

Это практическая инструкция для локальной разработки сайта, каталога и CMS. Она описывает текущую локальную сборку и не означает, что сайт опубликован или что production-инфраструктура готова.

## Что входит в проект

- `web/` — сайт на React и Vite: страницы, каталог, SEO-страницы и формы.
- `cms/` — Strapi 5, локальная SQLite-база, товары, заявки и SMTP-уведомления.
- `data/` и `scripts/` — исходная таблица каталога и скрипт подготовки seed-данных.
- `docs/SEO_REPORT.md` и `docs/SEO_SOURCES.md` — SEO-решения, источники и схема публикации.
- `deploy/nginx-static.conf.example` — пример раздачи статических HTML-страниц через Nginx.
- `PROJECT_STATUS.md` — техническое состояние, известные риски и незакрытые задачи.

## Первый запуск

Нужны Node.js 20–26 и npm. В корне проекта выполните:

```bash
npm install --prefix cms
npm install --prefix web
```

Запустите CMS в первом окне терминала:

```bash
npm run dev:cms
```

В другом окне, также из корня проекта, запустите сайт:

```bash
npm run dev:web
```

Откройте сайт на http://localhost:5173, панель Strapi — на http://localhost:1337/admin. При первом входе Strapi предложит создать администратора. REST API каталога доступен на http://localhost:1337/api/products.

Чтобы остановить каждый сервер, нажмите `Ctrl+C` в соответствующем окне. Данные локальной CMS хранятся в SQLite-файле внутри `cms/.tmp/`; не удаляйте его, если хотите сохранить локальный каталог и заявки.

## Работа с каталогом и заявками

В панели Strapi откройте **Content Manager → Товар**. Создайте или отредактируйте запись, заполните обязательные поля, затем нажмите **Publish**. Изменения API становятся доступны без пересборки dev-сайта. Для статического SEO HTML после изменения каталога обновите утверждённые seed-данные и заново соберите сайт; порядок описан в `docs/SEO_REPORT.md`.

Заявки сайта сохраняются в CMS. Если SMTP настроен, сервер отправляет уведомление на заданный адрес. Статус «Принято SMTP» означает, что почтовый сервер принял письмо к обработке, но сам по себе не доказывает доставку во входящие. Автоматического повтора при ошибке отправки нет — такие заявки требуют ручной обработки. Не помещайте SMTP-пароль во frontend или переменные `VITE_*`.

Локальная SMTP-конфигурация описана в `cms/.env.example`; реальные значения задаются только в игнорируемом Git файле `cms/.env`. Не добавляйте `.env` в коммит и не вставляйте пароли в переписку или логи.

## Часто используемые команды

Из корня:

```bash
npm run build
npm run lint --prefix web
npm run qa:visual
npm --prefix web run qa:seo
```

`qa:visual` требует одновременно запущенных CMS и web. Для SEO smoke сначала соберите web; команда проверяет готовую статическую сборку. Предварительный просмотр production-сборки:

```bash
npm --prefix web run preview
```

Vite сообщит адрес preview-сервера, обычно http://localhost:4173. Сборка создаёт отдельные HTML для известных маршрутов; неизвестные маршруты должны возвращать HTTP 404 на хостинге.

### Smoke-проверка CMS

Текущие корневые команды `npm run cms:smoke:add` и `npm run cms:smoke:cleanup` могут завершиться ошибкой конфигурации базы, так как Strapi запускается не из каталога `cms`. Используйте рабочий вариант из отдельного терминала:

```bash
cd cms
node scripts/cms-smoke.cjs
node scripts/cms-smoke.cjs --cleanup
```

Первый вызов временно создаёт опубликованный тестовый товар `E2E-9000`; второй удаляет его. После теста выполните cleanup.

## Обновление исходного Excel-каталога

Исходный файл хранится в `data/`. Скрипт `scripts/extract_products.py` формирует seed JSON для web и CMS. Команда в корневом `package.json` сейчас ссылается на локальный runtime конкретной машины и может не работать на другом компьютере. При переносе проекта установите Python с нужной библиотекой для XLSX и запускайте скрипт напрямую:

```bash
python3 scripts/extract_products.py
```

Перед импортом проверьте источник и результат; автоматического обновления уже существующих записей CMS seed не выполняет.

## Публикация сайта

Сначала выполните production-сборку и настройте публичные `VITE_SITE_URL` и `VITE_CMS_URL`. При публикации статического сайта хостинг должен раздавать соответствующий HTML для каждого чистого URL и отдавать настоящий HTTP 404 для неизвестных адресов. Пример Nginx-конфигурации: `deploy/nginx-static.conf.example`.

Этот репозиторий сам по себе не разворачивает сайт. Локальная сборка не подтверждает состояние публичного домена. Для production CMS отдельно нужны PostgreSQL, постоянное хранилище загрузок, резервные копии с проверенным восстановлением, ограничения CORS, защита публичной формы, TLS и мониторинг. Актуальный чек-лист — в `PROJECT_STATUS.md`.

## Если что-то не запускается

- **Команда `npm` не найдена или версия Node не подходит:** установите Node.js 20–26 и откройте новый терминал.
- **Порт 5173 или 1337 занят:** остановите уже работающий экземпляр либо используйте порт, который сообщит dev-сервер.
- **Сайт открылся, но каталог не обновляется:** проверьте, что CMS работает и товар опубликован. Frontend имеет seed fallback, поэтому видимый каталог сам по себе не подтверждает соединение с CMS.
- **Форма не отправляется:** проверьте доступность CMS/API и поля согласия; письмо также зависит от SMTP. Заявка может сохраниться даже при ошибке уведомления.
- **Изменения не появляются на production:** локальный Vite не обновляет публичный сайт; отдельно нужна сборка и публикация на настроенный хостинг.
