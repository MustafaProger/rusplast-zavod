# Девять SEO-статей — 10 октября 2026

## Задача и основание

Пользователь поручил изучить сайт, применить SEO-навыки, создать девять новых статей с тематическими изображениями и опубликовать на сервере. Разрешение охватывает публикацию этих материалов.

Перед работой прочитаны PROJECT_STATUS.md, README, инструкции CMS и SEO_AUTOPUBLISH. Зафиксированы существующие незакоммиченные изменения; исходники приложения не меняются этой задачей. Живая CMS на старте содержала **9 статей и 16 товаров**. Источник фактов — текущие опубликованные записи Strapi и публичные страницы, а не локальный снимок сборки.

## Применённые SEO-приёмы

- Самостоятельная задача читателя на каждую страницу, проверка пересечения с девятью старыми материалами.
- Ключевая тема в H1, title, начале текста, description и осмысленном alt; без фиксированной плотности ключей.
- Пять содержательных разделов на статью, практический пример, таблица либо контрольный список; прямой ответ во вступлении и итоговая рекомендация.
- Уникальные итоговые title 51–56 символов (в CMS 35–40, бренд добавляет сайт) и description 143–150 символов, ссылки на соответствующие категории, связанные статьи и форму запроса.
- Фактическая дата публикации, редакционная подпись, проверяемые источники. Цены и размеры в учебных примерах обозначены условными. Неподтверждённые свойства, нормативы, сроки и наличие не заявляются.
- Девять новых предметных ИИ-иллюстраций 1536×1024, по одной на тему, описательные alt, явное указание происхождения обложки во вступлении. Изображения не выдают за фотографии производства или конкретных товаров.
- Проверка серверного HTML, canonical, description, Open Graph, BlogPosting, sitemap и publication manifest после публикации.

Использованы инструкции навыков `seo-content`, `seo-content-brief` (принципы интента, пользы и метаданных) и `imagegen`. Отдельные оценки E-E-A-T и таблицы «топ-5» не рассчитывались: данных для достоверных рангов и оценок нет. Частотность, текущие позиции и конкуренция по ключам не измерялись. Выбор тем — редакционная гипотеза на основе сайта и публичной поисковой выборки, а не доказанный прогноз трафика.

Ориентир качества: [Google — полезный контент для людей](https://developers.google.com/search/docs/fundamentals/creating-helpful-content). Цель — самостоятельные рабочие памятки покупателю, а не обещание роста позиций за счёт количества страниц.

| Цена гофротрубы за метр и бухту | Коммерческое исследование | Различие стоимости потребности и закупаемых упаковок; условный расчёт бюджета |
| Клипсы для гофротрубы | Подбор комплектующих | Проверка назначения держателя, наружного диаметра и отдельных деталей комплекта |

| Перевозка гофротрубы | Логистический | Состав транспортной заявки и пример кубатуры без обещания вместимости машины |
| Ведомость гофротрубы для объекта | Планирование | Два представления: участки и свод по артикулам, контроль версий проекта |
| Цвет гофротрубы и обозначение трасс | Организация проекта | Разделение цвета, кода трассы и подтверждённых свойств; образец легенды |

Близкие темы разделены по результату: раскрой создаёт план отрезков, учёт остатков — проверенный свободный запас, график поставки — распределение по времени, ведомость — связь со спецификацией проекта. Это не девять вариантов одного ключевого запроса.

## Артефакты и проверка

- `articles/*.json` — точные подготовленные входные тексты, маркер `generated-cover` заменяется штатным publisher на CMS URL.
- `prepublication-checks.json` — структура, длины метаданных, объём текста и SHA-256 обложек.
- `output/seo-2026-10-10/` — исходный живой контекст, снимок старых статей и manifest, PNG, журналы публикации, полные квитанции и HTTP-проверки. Каталог исключён из Git.
- Текст и изображения просмотрены текущей сессией. Отдельная независимая редакторская сессия не запускалась; это ручной пакетный выпуск через штатный publisher, а не девять запусков планировщика Artel Operator.
- Публикация использует `scripts/publish-article.py` → фиксированный CMS CLI по SSH → Media Library «Блог» → Publish → проверка публичного manifest/H1/sitemap. Расписание оператора не меняется.

Итоговые результаты публикации и ссылки записываются в `publication-results.json` после завершения проверки. Индексация поисковиками и SEO-эффект оцениваются отдельно; наличие URL в sitemap не доказывает индексацию.
