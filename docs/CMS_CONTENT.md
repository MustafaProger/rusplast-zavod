# Редактирование сайта через CMS

Панель: [cms.rusplast-zavod.ru/admin](https://cms.rusplast-zavod.ru/admin). Используйте действующую учётную запись. Материалы находятся в **Content Manager**, изображения и PDF — в **Media Library**.

Инструкция относится к обновлённой CMS-схеме. Развёртывание этой версии и первоначальный перенос материалов на рабочем сервере подтверждаются отдельно при релизе.

## Где что менять

| Раздел Content Manager | Содержимое сайта | Поле файла |
| --- | --- | --- |
| **Товар** | Карточка каталога, характеристики и цена | `photo` — фотография |
| **Статья** | Блог, полный текст, обложка, источники, связанные статьи | `image` — обложка |
| **Документ** | Сертификаты и документы | `file` — PDF; `pages` — необязательные изображения страниц |
| **Заявка** | Обращения посетителей, доступные сотрудникам | Файл посетитель не загружает |

Названия коллекций русские; часть полей и кнопки Strapi могут отображаться по-английски. Ниже приведены точные имена полей.

## Сохранить и опубликовать — разные действия

**Save** сохраняет черновик. Чтобы показать запись посетителям, нажмите **Publish**. При правке уже опубликованного материала на сайте остаётся предыдущая опубликованная версия, пока вы не опубликуете изменения. **Unpublish** снимает материал с сайта.

После публикации подождите около 15 секунд и обновите страницу сайта. Сервер получает новый контент из CMS и обновляет HTML и sitemap без пересборки. Изменение не обязано появляться само в уже открытой вкладке. Эта схема работает на новом серверном runtime; статический предпросмотр разработчика остаётся снимком сборки.

Загрузка файла в Media Library сама по себе не меняет карточку: файл нужно выбрать в нужной записи и опубликовать эту запись.

## Фотографии товаров

1. Откройте **Content Manager → Товар** и найдите позицию по `sku` — артикулу.
2. В поле `photo` выберите фотографию из Media Library или загрузите новую.
3. Проверьте название, цвет, материал и диаметр на соответствие изображению.
4. Сохраните и нажмите **Publish**, затем проверьте карточку каталога и окно товара на сайте.

Для нового товара заполните название `name`, адресный идентификатор `slug`, уникальный артикул `sku`, материал, класс нагрузки, описание, цвет, наружный диаметр, длину бухты и цену. Цена указывается за метр, длина — в метрах на бухту.

Поле `image` типа строки оставлено для совместимости старых данных. **Новую фотографию выбирайте в `photo`**; вводить путь `/images/...` вручную не требуется. Не меняйте существующий артикул ради замены фотографии.

Если один файл используется несколькими материалами, изменение самого файла может затронуть их все. Для самостоятельной замены загрузите отдельный файл и выберите его в нужной записи. Не удаляйте используемые файлы из Media Library до замены связей.

## Статьи блога

Откройте **Content Manager → Статья**. Здесь хранится текст, а не только ссылка на внешний файл. Для новой записи нажмите **Create new entry**.

| Поле | Что указать |
| --- | --- |
| `title` | Заголовок статьи |
| `slug` | Постоянная часть адреса `/blog/slug`, латиницей через дефис |
| `seoTitle` | Заголовок страницы для поиска и вкладки браузера |
| `description` | Краткое описание статьи |
| `category` | Подпись категории |
| `image` | Обложка из Media Library |
| `imageAlt` | Содержательное описание изображения |
| `intro` | Вступление |
| `takeaway` | Главный практический вывод |
| `sections` | Разделы статьи в формате JSON |
| `sources` | Источники в формате JSON |
| `related` | Slug связанных опубликованных статей в формате JSON |
| `author` | Автор или редакция |
| `publishedOn` | Фактическая дата публикации материала |
| `modifiedOn` | Дата существенного обновления, если было |

Существующий `slug` лучше сохранять: он используется в ссылках. При необходимости нового адреса согласуйте перенаправление со специалистом. Даты `publishedOn` и `modifiedOn` — редакционные; служебные поля Strapi заполняет самостоятельно.

Содержимое `sections` — массив. Пример для вставки именно в это поле:

```json
[
  {
    "id": "raschet-obema",
    "title": "Как рассчитать количество",
    "paragraphs": [
      "Уточните длину каждой трассы и длину трубы в выбранной бухте.",
      "Необходимый запас зависит от проекта и способа монтажа."
    ],
    "list": [
      "Составьте перечень трасс.",
      "Уточните комплектацию с менеджером."
    ],
    "links": [
      { "label": "Каталог труб", "href": "/catalog" }
    ]
  }
]
```

Для каждого раздела нужны уникальный непустой `id`, заголовок `title` и массив абзацев `paragraphs`. Поля `list` и `links` необязательны. В текстовых полях вводится обычный текст: HTML-разметку вставлять не нужно. При необходимости раздел поддерживает таблицу `table` с полями `caption`, `headings` (массив строк) и `rows` (массив массивов строк).

Поле `sources` содержит массив ссылок на действительно использованные документы или страницы. Пример структуры:

```json
[
  { "label": "Каталог продукции", "href": "/catalog" }
]
```

Для сертификата выбирайте ссылку на соответствующий реальный PDF. Допускаются адреса сайта, начинающиеся с `/`, и полные адреса `https://` или `http://`. Проверяйте, что источник подтверждает утверждение статьи.

Поле `related` содержит только идентификаторы других статей, без `/blog/`. Например, `["slug-drugoy-stati"]`; если связей нет, укажите `[]`.

После сохранения и **Publish** проверьте `/blog` и полный адрес статьи: заголовок, дату, обложку, текст, источники и связанные материалы. Статья и её адрес добавляются в sitemap автоматически. `publicationInputSha256` и `imageGeneration` относятся к автоматическому выпуску; редактору не нужно менять их вручную.

`generated-articles.json`, старые массивы статей и файлы миграции больше не являются рабочим местом редактора. Правка выполняется в CMS.

## PDF-документы

1. Откройте **Content Manager → Документ → Create new entry** или существующий документ.
2. Заполните `title` — название, `slug` — постоянный идентификатор, `subtitle` — номер, срок действия или пояснение.
3. В обязательном поле `file` загрузите PDF либо выберите PDF из Media Library.
4. При желании добавьте в `pages` изображения страниц по порядку. Это необязательное поле: **одного PDF достаточно**.
5. Установите `sortOrder`: меньшие числа показываются раньше.
6. Сохраните и нажмите **Publish**. Проверьте карточку в разделе «Сертификаты и документы», открытие и скачивание PDF.

PDF проверяется при загрузке и назначении записи. Переименование другого формата в `.pdf` не делает его PDF. Чтобы обновить сертификат, выберите новый файл и поправьте номер/сроки; не указывайте неподтверждённую действительность документа.

`pages` используется для галереи сканов. Без него посетитель получает доступ к PDF через карточку документа; вручную готовить картинки всех страниц не требуется. При добавлении сканов следите, чтобы они относились к выбранному PDF и шли в правильном порядке.

Существующие адреса `/documents/<slug>.pdf` сохранены для ссылок из статей. Основные карточки берут файлы из CMS. Не меняйте `slug` опубликованного документа без проверки старых ссылок.

## Папки Media Library

- **Товары** — фотографии каталога; имя файла содержит артикул.
- **Блог** — обложки статей. Новые обложки Artel Operator сразу сохраняет сюда.
- **Документы** — отдельная подпапка для каждого сертификата, письма или протокола. Внутри лежат исходный PDF и изображения его страниц с номерами.
- **Оформление сайта** — четыре изображения шапки и блока производства.

При ручной загрузке сначала откройте нужную папку. Для нового документа создайте подпапку с его названием и номером, загрузите туда PDF и, при необходимости, сканы. Затем выберите эти файлы в записи «Документ». Перемещение файлов между папками не меняет ссылки и связи с записями.

Отдельная коллекция «Изображение сайта» удалена. Иллюстрации тематических разделов берутся из фотографий соответствующих товаров. Четыре изображения оформления хранятся в Media Library; их назначение блокам задано в конфигурации сайта `web/src/data/site-media.json`.

## Автоматические статьи и реалистичные обложки

Artel Operator использует опубликованный каталог и документы CMS, пишет и проверяет статью, генерирует отдельную фотореалистичную обложку, загружает её в Media Library и публикует статью в этой же коллекции. Обложка — редакционная иллюстрация; её не следует выдавать за фотографию конкретного цеха компании.

После автоматического выпуска материал можно найти в **Статья** и проверить как обычную запись. Повтор сбойного выпуска использует сохранённые текст и изображение; автоматизация не должна перезаписывать редакторскую правку. Подробности и эксплуатационные условия: [инструкция оператора](SEO_AUTOPUBLISH.md).

## Персональные данные и первоначальный перенос

Заявки доступны сотрудникам в **Заявка**. Не загружайте заявки, клиентские контакты и приватные документы в публичную Media Library: файлы, используемые сайтом, доступны посетителям по ссылке.

Правовые страницы `/privacy`, `/consent`, `/terms` обновляются вместе с кодом приложения. Организационные действия по Роскомнадзору, хранению, почте и резервным копиям перечислены в [аудите персональных данных](PRIVACY_REVIEW-2026-09-23.md).

Если новые коллекции пока пусты, первоначальный перенос выполняет технический специалист по [инструкции миграции](../cms/CONTENT-MIGRATION.md). Не нужно вручную создавать дубликаты всех старых материалов. Запуск или перезапуск CMS не запускает повторный импорт.
