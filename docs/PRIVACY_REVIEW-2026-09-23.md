# Проверка обработки персональных данных — 23.09.2026

Обновлены политика, отдельное согласие и обработка заявки в коде. Это не заключение об отсутствии любых штрафов: соответствие зависит также от реальных договоров, размещения баз, уведомлений Роскомнадзора и работы сотрудников. Ниже отдельно указаны подтверждённые факты и вопросы, которые нельзя установить из исходников.

## Что проверено

- Реквизиты Оператора из ранее предоставленного документа, зафиксированного в `docs/SEO_SOURCES.md`: ООО «РУСПЛАСТЗАВОД», ИНН 9721122788, ОГРН 1217700129602; г. Москва, проспект Андропова, д. 10, помещение 98. Свежая выписка ЕГРЮЛ в рамках этой проверки не получалась.
- Форма собирает имя, телефон, email, необязательный комментарий и выбранные товары. Данные сохраняются в Strapi; уведомление с содержимым заявки отправляется через SMTP. Удалённые значения `SMTP_HOST`, `SMTP_USER`, `LEAD_EMAIL_TO` проверены без вывода паролей: `smtp.mail.ru`, `rusplastfactory@mail.ru`, `rusplastfactory@mail.ru`. Секреты не включены в отчёт.
- Production размещён в инфраструктуре, описанной как Рег.ру / Рег.облако; PostgreSQL находится в отдельном Docker volume, порт базы не опубликован. Юридическое лицо исполнителя, договор поручения и физический адрес ЦОД по исходникам не подтверждаются.
- В браузере сохраняется только корзина `rpz-cart` (артикулы и количество). Поиск по исходникам не обнаружил счётчиков Метрики/Google Analytics, рекламных трекеров или сторонних форм. Шрифты подключены локально.
- Используются серверные HTTP-журналы и резервные копии. В deployment есть ограничение размера/числа Docker-журналов; это не равно ограничению срока хранения по дням. Документированная резервная копия включает заявки и локальную копию архива на Mac.
- В первоначальной редакции уже были отдельная незаполненная отметка согласия, ссылка на текст согласия и серверная проверка редакции `2026-09-05`. Эти элементы сохранены и усилены, а не представлены как отсутствовавшие.

## Сравнение и исправления

| Было | Стало | Значение |
| --- | --- | --- |
| Краткая политика без юридического адреса и описания фактических технических исполнителей | Полная редакция `2026-09-23`: адрес, цели, данные, основания, операции, исполнители, локальное хранилище, технические запросы, права, сроки и порядок обращения | Посетитель получает описание конкретного процесса заявки |
| Публичный контакт по вопросам персональных данных — Gmail | Подтверждённый рабочий ящик `rusplastfactory@mail.ru` в правовых документах и блоке контактов | Новые обращения не предлагается направлять в Gmail; это не доказывает прекращение всех прежних трансграничных процессов |
| Версия и время согласия, но без сохранённого текста | Единый JSON согласия для сайта и CMS; сервер сохраняет текст, SHA256, редакцию, время и способ подтверждения | Можно восстановить именно редакцию, связанную с заявкой; браузер не задаёт содержимое доказательства |
| Общий CRUD-маршрут заявок, защита чтения зависела от настроек роли | Content API предоставляет только создание; просмотр/работа сотрудников остаются в защищённом Content Manager CMS | Ошибка настройки публичной роли не открывает чтение/изменение/удаление через эти маршруты |
| Ответ API возвращал созданную запись | Ответ содержит только номер `documentId` | Контакты, комментарий и текст согласия не отражаются в публичном ответе |
| `products` сохранялся из клиентского JSON целиком | Сервер принимает артикул/количество и собирает ограниченный снимок опубликованного товара из CMS | Лишние поля, URL изображений и подменённые цены/названия не сохраняются и не рассылаются |
| Годовой срок в политике без машинно-читаемой отметки | Для новых заявок записывается `retentionExpiresAt`; уточнено прекращение раньше при достижении цели/отзыве | Это контрольный срок для ответственного сотрудника, **не работающий процесс автоматического удаления** |

Согласие не объединено с пользовательским соглашением; checkbox по-прежнему пуст по умолчанию. API отклоняет отсутствие согласия, строку `"true"`, `false` и устаревшую редакцию до записи и отправки уведомления. Старые записи и их версии не переписываются новой датой; старые согласия не объявляются согласиями с новой редакцией.

## Что остаётся сделать владельцу и ответственному за данные

1. **Уведомление Роскомнадзора.** Найти запись ООО по ИНН, сверить сведения с реальными целями/категориями/местом баз и при необходимости подать или актуализировать уведомление. Автоматизированная форма сайта обычно требует такого уведомления; наличие записи не установлено. Отсутствие найденной записи в этой проверке не объявляется доказанным нарушением.
2. **Размещение и исполнители.** По договору хостинга/панели подтвердить физическую страну размещения рабочей базы, всех реплик и резервных копий. Уточнить юридические лица хостера и почтового исполнителя и оформить условия поручения по ст. 6. Геолокация IP, российский домен и бренд провайдера сами по себе доказательством не являются. После проверки дополнить реквизиты исполнителей в политике/согласии при необходимости и выпустить новую редакцию.
3. **Прежний Gmail и внешние сервисы.** Проверить пересылки рабочего ящика, почтовые клиенты, архивы и старые контакты Gmail. Код формы отправляет уведомление в подтверждённый Mail.ru; это не позволяет утверждать, что все прежние копии из Google удалены или трансграничная передача нигде не происходит. Для существующего внешнего процесса отдельно проверить основания, ограничения ст. 12 и требования уведомления. Изменение политики не исправляет такой процесс само по себе.
4. **Сроки и удаление.** Назначить сотрудника, который регулярно проверяет достижение цели, отзывы и `retentionExpiresAt`, удаляет ненужную заявку в CMS и связанные письма, обеспечивает удаление у исполнителей и оформляет подтверждение уничтожения. Договорные/обязательные документы отделять по самостоятельному основанию, а не оставлять любую заявку навсегда. Уточнить и утвердить конкретный срок технических журналов и жизненный цикл резервных копий. Удаление одной записи не удаляет её из дампов, архивов на Mac и почты; нельзя обещать соблюдение срока до внедрения этой процедуры. Код намеренно не уничтожает существующие обращения автоматически без определения других законных оснований и копий.
5. **Доступ, запросы и инциденты.** Утвердить ответственного, список доступов и необходимые локальные документы; подтвердить, что рабочий Mail.ru регулярно читается. Обеспечить обработку запросов и отзывов, журнал обращений и порядок действий/уведомлений при инциденте (включая первоначальное уведомление за 24 часа и результаты внутреннего расследования за 72 часа в предусмотренных законом случаях). Сайт не подтверждает наличие этих организационных мер.

Новая публичная политика описывает обязанности, а не выдаёт неподтверждённые утверждения о регистрации в реестре, стране сервера, оформленных договорах или автоматическом уничтожении. Гарантировать отсутствие штрафов на основании одного изменения текста невозможно.
