## Реализация

- 18 готовых HTML-страниц: 14 содержательных страниц для sitemap, три правовые и 404.
- Текст, H1, title, description, canonical, Open Graph, Twitter Cards и JSON-LD присутствуют в исходном HTML production-сборки. React подключает интерактивность к тому же содержимому.
- `robots.txt` и `sitemap.xml` генерируются из единого списка маршрутов. В sitemap нет 404, правовых документов, параметров фильтра и выдуманного `lastmod`.
- Organization, WebSite, WebPage/CollectionPage, BreadcrumbList, BlogPosting, ItemList и Service. В разметке нет вымышленных рейтингов, отзывов, авторов, доступности или специальных цен. Дата 18.09.2026 обозначает подготовку материала (`dateCreated`); `datePublished` не подставлена до публичного выпуска.
- У статей есть понятные URL, оглавление, краткий ответ, тематические разделы, таблицы/списки, источники, ссылки на товары и связанные публикации.
- Каталог и страницы ПВХ/ПНД показывают все соответствующие позиции в исходном HTML. Клиентские фильтры не создают отдельные индексируемые URL. Добавлен фильтр цвета.
- Заголовок главной описывает продукцию, добавлены сведения о производстве, навигация по категориям, ссылка на СТМ и блок блога.
- Изображения подготовлены в WebP с вариантами размеров, alt и зарезервированными габаритами. Изображение главной: 2 084 507 → 116 634 байта (1280 px); производственные бухты: 2 190 036 → 95 244 байта. Это измерение веса файлов, не оценка полевых Core Web Vitals.
- Состояние выбора товаров восстанавливается после подключения React без расхождений с готовым HTML. Отправка формы без JavaScript отключена, доступен контактный телефон; персональные данные не уходят через GET.
- Неизвестные адреса получают страницу 404 с noindex; сервер предварительного просмотра возвращает настоящий HTTP 404. Для хостинга подготовлены правила чистых адресов.

## Проверки

Команды из корня:

```sh
npm --prefix web run build
npm --prefix web run lint
npm --prefix web run qa:seo
npm run qa:visual
```

`qa:seo` поднимает изолированный сервер готовой сборки, проверяет 18 страниц без JavaScript, уникальность title/description, canonical, JSON-LD, ссылки и фрагменты, sitemap, robots, HTTP 404 и перенаправления. Проверяет 40 сочетаний страницы/экрана (1440, 768, 390, 320 px), фильтрацию, сохранение выбора между страницами, открытие формы и просмотр сертификата. Сетевой ответ каталога в этом тесте — fixture из существующего seed; формы не отправляются, CMS и SMTP не тестируются.

Результат локального прохода: 18 страниц, 14 URL в sitemap, 83 внутренних ссылки/фрагмента; 6 статей по 525–571 слов основного блока с источниками; горизонтальное переполнение 0 px на всех проверенных размерах; ошибок гидратации нет. Скриншоты и JSON-результат по умолчанию сохраняются во временную папку `rusplast-seo-qa` (можно задать `QA_OUTPUT_DIR`).

## Сборка и публикация

1. Указать `VITE_SITE_URL` — действительный HTTPS-домен без пути. По умолчанию используется существующий в проекте `https://rusplast-zavod.ru`. `VITE_CMS_URL` — публичный адрес API, не localhost на опубликованном сайте. В `VITE_*` нельзя помещать секреты.
2. Выполнить production-сборку и разместить **всё** содержимое `web/dist`, включая вложенные HTML, документы, изображения, sitemap и robots.
3. Для чистого `/blog` отдавать `blog.html`, для `/blog/slug` — `blog/slug.html`. Не использовать глобальный SPA fallback на главную: он уничтожает правильный исходный HTML и создаёт soft 404.
4. Для Vercel с корнем проекта `web` предусмотрен `web/vercel.json`: cleanUrls + trailingSlash:false. Для Nginx пример в `deploy/nginx-static.conf.example`. Фактические домены, TLS и API настраиваются на выбранном сервере.
5. Проверить публичные HTML и статус 404, изображения, canonical, редиректы и sitemap уже на сервере; затем отправить sitemap в Яндекс Вебмастер и Google Search Console из аккаунтов владельца.

Предварительный просмотр production-сборки: `npm --prefix web run preview`, адрес `http://127.0.0.1:4173/blog`. Режим разработки доступен на `http://127.0.0.1:5173/blog`; исходный HTML dev-сервера не является SEO-артефактом.

Текущий каталог в статической сборке формируется из `web/src/data/products.json`, затем браузер обновляет его через существующий API. При изменении ассортимента в CMS нужно синхронизировать seed с утверждёнными данными и пересобрать сайт, чтобы исходный HTML тоже обновился. Автоматическая синхронизация seed и CMS не добавлена. В исходном XLSX обнаружены противоречия, поэтому новый файл не импортирован поверх базы автоматически.

Полевые Core Web Vitals, реальные поисковые позиции, трафик и индексация не измерялись: нет подключённых данных Вебмастера/Search Console/аналитики. Внешнее продвижение и рассылка ссылок не выполнялись.

## Использованные SEO-навыки и первичные рекомендации

Применены `seo`, `seo-technical`, `seo-content`, `seo-schema`, `seo-sitemap`, `seo-images`. Их рекомендации использованы по применимости к сайту производителя; инструменты платной аналитики, массовые посадочные страницы и неподтверждённые показатели не имитировались.

- [Google: JavaScript SEO и предварительный рендеринг](https://developers.google.com/search/docs/crawling-indexing/javascript/javascript-seo-basics) — доступный исходный HTML и согласованность метаданных.
- [Google: Article / BlogPosting](https://developers.google.com/search/docs/appearance/structured-data/article) — разметка, соответствующая статье, без вымышленных сведений.
- [Google: canonical URL](https://developers.google.com/search/docs/crawling-indexing/consolidate-duplicate-urls) — один адрес страницы, согласованный с sitemap.
- [Яндекс: Sitemap](https://yandex.ru/support/webmaster/ru/controlling-robot/sitemap) — карта существующих страниц и ссылка из robots.txt.
