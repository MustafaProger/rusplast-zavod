# Контент и Media Library

CMS управляет товарами, статьями и документами. Изменения сохраняются как черновик; сайт читает опубликованные записи. Публичные API `products`, `articles`, `documents` всегда возвращают опубликованную версию, даже при передаче `status=draft`. Запись через публичную роль и загрузка файлов этой роли не разрешаются.

## Поля

- **Товар → photo**: одна фотография из Media Library. Старое поле `image` оставлено для совместимости миграции. Новый товар должен использовать `photo`.
- **Статья → image**: обязательное изображение; `imageAlt` — его описание. `publishedOn` / `modifiedOn` — даты материала, независимо от служебных дат Strapi. `sections`, `sources`, `related` сохраняют существующую структуру JSON (см. исходный снимок `src/data/content-migration.json`). `publicationInputSha256` и `imageGeneration` — закрытая техническая информация генератора, отсутствует в публичном API.
- **Документ → file**: PDF, проверяются MIME, расширение и сигнатура при загрузке. Поле проверяет, что выбранный в библиотеке файл — PDF. **pages**: необязательные изображения страниц для галереи; **sortOrder**: порядок карточек. PDF можно загрузить без предварительного создания сканов. В Media Library замена PDF другим типом файла запрещена.


Содержимое JSON статьи:

```json
{
  "sections": [{"id":"section-id","title":"Заголовок","paragraphs":["Абзац"],"list":["Пункт"],"links":[{"label":"Каталог","href":"/catalog"}]}],
  "sources": [{"label":"Источник","href":"/documents/example.pdf"}],
  "related": ["slug-drugoy-stati"]
}
```

Необязательная таблица раздела: `table: {caption, headings: string[], rows: string[][]}`. Сайт использует обычный текст, а не HTML.

## Явная миграция существующего сайта

Снимок от 23.09.2026 содержит 16 товаров, 7 статей, 6 PDF, 26 изображений страниц и 4 изображения оформления. Исторический массив `siteImages` в пакете содержит только описания файлов; отдельная коллекция для них не создаётся (три описания используют картинки товаров). Он сохраняет тексты, ссылки, связанные статьи и изображения, использовавшиеся сайтом. Автоматический посев товаров при запуске удалён: редактор может удалить любую запись, и перезапуск не восстановит её.

Из корня репозитория подготовить переносимый пакет (без ключей и базы):

```sh
node cms/scripts/prepare-content-migration.cjs /tmp/rusplast-content-media-v1
```

Скопировать весь каталог на сервер или в контейнер CMS. Docker-образ CMS должен содержать `scripts/`, а подключённый том `public/uploads` должен быть доступен на запись. Применять после сборки обновлённой CMS, с резервной копией БД и uploads. Чтобы не запускать конкурентно синхронизацию схемы в двух процессах, на время применения остановить сервис CMS и выполнить команду в одноразовом контейнере с той же конфигурацией и томами.

Проверить пакет из каталога CMS (не подключается к базе, ничего не записывает):

```sh
node scripts/migrate-content.cjs --bundle /tmp/rusplast-content-media-v1
```

Применить:

```sh
node scripts/migrate-content.cjs --bundle /tmp/rusplast-content-media-v1 --apply
```

Миграция проверяет SHA-256 всех файлов до первой записи. Файлы загружаются через сервис Strapi Upload и появляются в Media Library. Товар сопоставляется по `sku`, статья и документ — по `slug`. У существующих записей добавляются только отсутствующие медиа-связи; тексты, цены и уже выбранные редактором файлы сохраняются. Старые общие пути `/images/pipe-*.jpg` в товарах заменяются связью с индивидуальным изображением артикула, которое сайт уже показывал до миграции; нестандартные изображения редактора сохраняются. Связи черновика и опубликованной версии обновляются отдельно без публикации незавершённых правок. Новые записи публикуются с исходным содержимым.

Журнал `core/rusplast-migration/content-media-v1` хранит выполненные записи и загруженные файлы. Повторный запуск после завершения не создаёт дубликаты и не возвращает записи, удалённые редактором. Прерванный запуск можно повторить. Не удаляйте журнал для повторной загрузки: это изменит указанное поведение.

Старые `/documents/*.pdf` остаются корректными адресами в существующих статьях; переход на CMS не требует менять внешние ссылки на документы. Основные карточки документов получают файл и изображения из CMS.

## Проверка

Из `cms/`:

```sh
npx strapi ts:generate-types
npx tsc
node --test tests/content-migration.test.cjs tests/article-content.test.cjs
```

Интеграционный тест создаёт отдельную временную SQLite-базу, импортирует все 59 файлов, проверяет сохранность редакторского черновика, контрольные суммы, отсутствие повторных загрузок, невосстановление удалённой статьи и запрет поддельного PDF. HTTP-проверки подтверждают чтение опубликованных материалов и запрет анонимной записи/загрузки. Проверки структуры JSON отклоняют некорректные разделы, повторяющиеся идентификаторы и небезопасные адреса ссылок. Временные файлы и база удаляются после теста; рабочая локальная база не используется.

## Организация Media Library

После импорта выполните проверку и примените сортировку:

```sh
node scripts/organize-media.cjs
node scripts/organize-media.cjs --apply
```

Без `--apply` команда только строит план. Файлы распределяются по папкам «Товары», «Блог», «Документы» (подпапка на документ) и «Оформление сайта». Меняются только папка и технические импортные названия; URL, физические файлы, ID и связи записей сохраняются. Редакторские имена и неизвестные файлы сохраняются. Повторный запуск не создаёт дубликаты папок или файлов.

Коллекция `site-image` удалена. Фронтенд читает фотографии тематических разделов из товаров, а пути четырёх изображений оформления — из `web/src/data/site-media.json`. Перед удалением модели на действующем сервере сначала обновите фронтенд, чтобы он больше не запрашивал `/api/site-images`. Сделайте резервную копию БД и uploads. Пока старая модель ещё доступна, выполните `node scripts/retire-site-images.cjs` для проверки, затем `node scripts/retire-site-images.cjs --apply`: нативное удаление семи документов убирает их медиа-связи, сохраняя все загрузки. После этого обновите образ CMS и выполните сортировку. Скрипт проверяет неизменность ID, URL и хешей файлов в транзакции.
