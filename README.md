# РУСПЛАСТЗАВОД — новый сайт и CMS

Монорепозиторий содержит адаптивный React/Vite-сайт и Strapi 5 CMS. Каталог из 16 товаров импортирован из файла `data/Труба_гофрированная_характеристики_.xlsx`.

## Структура

- `web/` — клиентский сайт: каталог, фильтры, подробные характеристики, сбор позиций в заявку и формы.
- `cms/` — Strapi 5, SQLite для локальной разработки, типы контента «Товар» и «Заявка».
- `scripts/extract_products.py` — воспроизводимый импорт Excel в seed JSON для сайта и CMS.
- `design/` — утверждённые визуальные концепты основных блоков.

Для пошаговой инструкции по запуску, работе с каталогом и заявками, проверкам и публикации см. [гид по проекту](docs/USER_GUIDE.md).

## Локальный запуск

Требуется Node.js 20–26 и npm.

```bash
npm install --prefix cms
npm install --prefix web
npm run dev:cms
```

Во втором терминале:

```bash
npm run dev:web
```

- Сайт: http://localhost:5173
- CMS: http://localhost:1337/admin
- REST-каталог: http://localhost:1337/api/products

При первом открытии `/admin` Strapi предложит создать локального администратора. Пароль хранится только в Strapi и не нужен фронтенду. Публичным пользователям разрешены только чтение каталога и создание заявки; редактирование товаров остаётся закрытым.

## Добавление товара

1. Откройте Strapi → **Content Manager** → **Товар** → **Create new entry**.
2. Заполните обязательные поля: название, slug, артикул, материал, класс нагрузки, описание, цвет, внешний диаметр, длину бухты и цену.
3. В поле `image` укажите путь к изображению сайта, например `/images/pipe-black.jpg`, либо подключите Media Library перед production-деплоем.
4. Нажмите **Publish**. Новый товар автоматически появится в каталоге без пересборки фронтенда.

## Импорт обновлённого Excel

Замените исходный файл в `data/` и при необходимости путь `SOURCE` в скрипте, затем выполните:

```bash
npm run catalog:extract
```

Seed выполняется автоматически только для пустой базы, поэтому существующие товары CMS не перезаписываются.

## Проверки

```bash
npm run build
npm run cms:smoke:add
npm run cms:smoke:cleanup
```

Smoke-сценарий временно создаёт опубликованный товар с SKU `E2E-9000`; команда cleanup удаляет только эту тестовую позицию. Если корневые smoke-команды падают из-за рабочей директории Strapi, используйте инструкции в [гиде](docs/USER_GUIDE.md#smoke-проверка-cms).

## Production

Для production следует заменить SQLite на PostgreSQL, настроить постоянное хранилище Strapi uploads, перенести SMTP-настройки в окружение сервера и задать `VITE_CMS_URL` адресом публичного API. Секреты Strapi находятся в `cms/.env` и исключены из Git.

## Почтовые уведомления о заявках

В `cms/.env` задаются `SMTP_HOST`, `SMTP_PORT`, `SMTP_SECURE`, `SMTP_USER`, `SMTP_PASSWORD` (пароль приложения) и `LEAD_EMAIL_TO`. Пример без пароля — `cms/.env.example`. Для Mail.ru используются `smtp.mail.ru`, порт 465 и TLS. После изменения конфигурации перезапустите CMS. Пароль нельзя помещать в переменные `VITE_*`: они доступны посетителям сайта.

При отправке формы заявка сначала сохраняется в CMS, затем уведомление отправляется на `LEAD_EMAIL_TO`. В письме есть номер заявки, контакты, комментарий, артикулы, количество и предварительная стоимость выбранных позиций. Ответ на письмо адресуется клиенту. Клиенту автоматические письма не отправляются.

В CMS доступны поля `notificationStatus`, `notificationSentAt`, `notificationMessageId`. Статус «Принято SMTP» означает приём почтовым сервером, а не подтверждение доставки во входящие. При ошибке заявка сохраняется со статусом «Ошибка отправки»; автоматического повтора нет, такие заявки нужно обработать из CMS. Публичный API не раскрывает почтовые статусы и идентификаторы писем.

## Обновление интерфейса · 05.09.2026

- Светлая визуальная система, системный шрифт, полупрозрачная навигация и анимации с поддержкой reduced motion.
- Карусель актуальных сканов с увеличением, скачиванием оригинального PDF и клавиатурной навигацией. В раздел добавлены сертификат ЕАЭС на ПВХ, сертификат соответствия ПНД и информационное письмо на ПНД и клипсы.
- Единый выбор товаров для модальной и нижней формы. В браузере сохраняются только артикулы и количество; заявка в CMS содержит название, артикул, фотографию, число бухт, метраж и цену за метр.
- Успех формы показывается только после подтверждения CMS. При ошибке данные остаются в форме; скрытого сохранения контактов в localStorage больше нет.
- `/privacy`, `/terms`, `/consent` — отдельные правовые страницы. Документы доступны из формы без потери введённых данных. Сервер фиксирует версию согласия и время приёма заявки.
- Тексты правовых документов являются подготовленной редакцией: перед публикацией оператору нужно сверить реквизиты, сроки хранения и описанный порядок работы с реальными процессами. Они не подтверждают настройку хранения, удаления данных или production-инфраструктуры.

С 18.09.2026 production-сборка создаёт отдельный HTML для каждого маршрута, включая правовые страницы. Сервер должен отдавать соответствующие файлы по чистым URL, а неизвестные адреса — с HTTP 404. Глобальный SPA fallback на `index.html` больше не нужен. CMS отправляет уведомления менеджеру при настроенном SMTP. Правки выполнены локально; текущий публичный сайт не обновляется от запуска Vite.

## SEO и блог · 18.09.2026

Добавлены `/blog` и шесть статей, страницы ПВХ, ПНД, заказной FRHF, комплектующих и производства под СТМ. Полный текст и метаданные попадают в исходный HTML; sitemap и robots создаются при сборке.

```bash
npm --prefix web run build
npm --prefix web run qa:seo
npm --prefix web run preview
```

Предварительный просмотр: http://127.0.0.1:4173/blog. Перед публикацией задайте `VITE_SITE_URL` и публичный `VITE_CMS_URL`. После изменений товаров в CMS нужно также обновить утверждённый seed и пересобрать статический HTML; браузер по-прежнему получает товары из API.

Подробности: [SEO-отчёт и схема публикации](docs/SEO_REPORT.md), [разбор всех 10 документов](docs/SEO_SOURCES.md), [пример Nginx](deploy/nginx-static.conf.example).
