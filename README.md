# РУСПЛАСТЗАВОД — сайт и CMS

Сайт на React/Vite и Strapi 5. **Рабочий источник контента — Strapi:** товары и их фотографии, статьи с обложками, PDF-документы и изображения разделов. Файлы хранятся в **Media Library**; записи CMS связывают файл с конкретным материалом.

В обновлённой реализации сервер Node формирует HTML и sitemap из опубликованного содержимого CMS. После **Publish** изменения видны при новом открытии страницы или обновлении, обычно в течение 15 секунд. Пересборка для изменения контента не нужна. Черновики посетителям не показываются.

Эта инструкция описывает текущий код. Состояние публичного домена и применение миграции проверяются отдельно после выпуска; локальная сборка сама по себе ничего не публикует.

## Структура

| Каталог | Назначение |
| --- | --- |
| `web/` | React-интерфейс, серверный HTML, каталог, блог, документы, формы |
| `cms/` | Strapi: «Товар», «Статья», «Документ», «Заявка» |
| `cms/src/data/content-migration.json` | Исходный пакет разовой миграции; не действующая база контента |
| `web/src/data/cms-snapshot.json` | Снимок CMS для сборки и статического предпросмотра; не источник production |
| `scripts/` | Подготовка источников, контекст и публикация статей оператора |
| `deploy/` | Docker, маршрутизация, выпуск и резервное копирование |

В Git хранятся исходники, используемые сайтом файлы, исходные данные для импорта и рабочие инструкции. Временные результаты проверок, экспорты, логи и материалы генерации исключены через `.gitignore`. Резервные копии и рабочие заметки храните вне папки проекта; `cms/.tmp/data.db`, `cms/public/uploads/` и локальные `.env` нужны для работы CMS и не являются мусором.

## Локальный запуск

Нужны Node.js 22 (совпадает с Docker runtime) и npm. Реальные секреты CMS задаются в исключённом из Git `cms/.env`; образец — `cms/.env.example`.

```sh
npm ci --prefix cms
npm ci --prefix web
npm run dev:cms
```

Во втором терминале из корня проекта:

```sh
npm run dev:web
```

Сайт: [localhost:5173](http://localhost:5173). CMS: [localhost:1337/admin](http://localhost:1337/admin). При первом запуске пустой локальной CMS создайте администратора. В рабочую CMS входят существующей учётной записью.

Пустая база не заполняется автоматически при запуске. Для переноса исходного каталога, статей и файлов используется [явная миграция](cms/CONTENT-MIGRATION.md). Перезапуск не восстанавливает материалы, которые редактор удалил.

## Сборка и проверка

```sh
npm run build --prefix web
npm run build --prefix cms
npm run lint --prefix web
node --test cms/tests/lead-consent.test.cjs cms/tests/notification.test.cjs
```

Для обновления **локального снимка** из доступной CMS:

```sh
npm run cms:sync --prefix web
```

По умолчанию снимок читается с `https://cms.rusplast-zavod.ru`. Для другой CMS задайте `CMS_URL` и `CMS_PUBLIC_URL`. Команда только читает CMS и обновляет `web/src/data/cms-snapshot.json`; она не публикует статьи и не заменяет редактирование в Strapi.

После сборки запустить runtime, который читает CMS при запросах:

```sh
CMS_INTERNAL_URL=http://localhost:1337 CMS_PUBLIC_URL=http://localhost:1337 npm run start --prefix web
```

Адрес по умолчанию: [127.0.0.1:4173](http://127.0.0.1:4173). `npm run preview --prefix web` — отдельный **статический** просмотр снимка из `dist`, пригодный для проверки сборки; его содержимое не обновляется публикацией в CMS.

## Production

Действующая архитектура: PostgreSQL, постоянный том Strapi uploads, CMS и web runtime Node. Web Docker-образ получает `web/dist`, `web/dist-server`, `web/scripts/server.mjs` и `web/package.json`. Перед выпуском требуется `npm run build --prefix web`; одного каталога `dist` для runtime недостаточно.

Серверные `CMS_INTERNAL_URL` и `CMS_PUBLIC_URL` определяют внутренний адрес CMS и публичные URL media. `VITE_SITE_URL` задаёт canonical-домен, `VITE_CMS_URL` — доступный браузеру API при сборке. Секреты нельзя помещать в `VITE_*`.

Node runtime формирует HTML, `/sitemap.xml` и `/publication-manifest.json` из актуальной CMS с коротким серверным кешем. Если CMS недоступна после истечения кеша, сервер возвращает 503, а не восстанавливает удалённые статьи из старого снимка.

## Заявки и почта

Форма сначала сохраняет заявку в CMS, затем уведомляет рабочую почту через SMTP. Сотрудники открывают **Content Manager → Заявка**. «Принято SMTP» означает приём почтовым сервером, а не подтверждение доставки во входящие. При ошибке уведомления заявка остаётся сохранённой; автоматического повтора письма нет.

Согласие предоставляется отдельной пустой отметкой. CMS фиксирует редакцию, точный текст, SHA256, время и способ подтверждения. Публичный API заявок предоставляет только создание. Срок `retentionExpiresAt` помогает ответственному контролировать хранение, но не запускает автоматическое удаление из CMS, почты и резервных копий. Обязательные организационные действия перечислены в [аудите персональных данных](docs/PRIVACY_REVIEW-2026-09-23.md).
