# Несколько проектов на сервере Artel

Сервер: `130.49.151.239`. Caddy работает через systemd и принимает HTTP/HTTPS
на портах 80/443. Каждый проект запускается отдельно и публикует свой входной
порт только на `127.0.0.1`. Базы данных наружу не публикуются.

## Размещение

| Проект | Каталог | Входной порт |
| --- | --- | --- |
| FuelLead | `/opt/fuellead` | `127.0.0.1:18080` |
| Руспластзавод | `/opt/projects/rusplast-zavod` | `127.0.0.1:18081` |
| CMS Руспластзавода | тот же Compose-проект | `127.0.0.1:18082` |
| Следующий проект | `/opt/projects/ИМЯ` | свободный, начиная с 18083 |

Общий конфиг: `/etc/caddy/Caddyfile`; домены: `/etc/caddy/sites-enabled/*.caddy`.
Секреты каждого проекта хранятся в отдельном файле с правами `600` на сервере.
Конфигурация сертификатов Caddy сохраняется в `/var/lib/caddy`.

## Добавление проекта

1. Создать отдельный Compose-проект, сеть и постоянные volumes. Задать лимиты
   памяти и ротацию Docker-логов; не монтировать Docker socket в приложения.
2. Выбрать свободный порт и привязать его к loopback, например
   `127.0.0.1:18083:3000`. Проверить приложение через `curl` на сервере.
3. Создать A-запись домена на `130.49.151.239`. Проверить также AAAA: она не должна
   направлять посетителей на другой сервер. Сохранить почтовые MX/TXT-записи.
4. Скопировать `project.caddy.example` в `/etc/caddy/sites-enabled/ИМЯ.caddy`,
   указать домен и порт.
5. Выполнить `caddy validate --config /etc/caddy/Caddyfile`, затем
   `systemctl reload caddy`. Проверить HTTPS и журнал `journalctl -u caddy`.

DNS и HTTPS включаются после проверки приложения и настройки администратора.
Форму первичной регистрации администратора нельзя оставлять открытой в интернете.

## Проверки и обновления

`systemctl status caddy`, `ss -ltnp`, `docker stats --no-stream`, `free -m`, `df -h /`.
Проверять запас ресурсов перед каждым новым проектом: 4 ГБ RAM не гарантируют
вместимость произвольного числа приложений. Тяжёлые сборки запускать по одной.

FuelLead запускается с существующими файлами
`docker compose -f docker-compose.yml -f compose.production.yml up -d`.
В `compose.production.yml` frontend должен сохранять порт `127.0.0.1:18080:80`.
Обновление одного проекта не должно пересоздавать контейнеры других проектов.

Перед изменением конфигурации сохранять копию в `/opt/hosting/backups`.
Копии БД/файлов проекта и их проверяемое восстановление организуются отдельно;
резервная копия конфигурации не является резервной копией пользовательских данных.
